# Long-tail Chart

1. Confirm whether the user wants a conceptual diagram or a data-based chart,
   the axis meanings, labels, target slide, and any supplied data.
   Never invent numerical observations or a statistically meaningful split.
2. For real data, use an editable native chart with source values, units, and
   an appropriate axis scale. Sort categories only when meaningful and explain
   the order. Include required attribution. Do not substitute a decorative curve.
3. For a concept, use editable axes, a descending curve with a long tail, and
   short explanatory labels. Mark it explicitly as "Conceptual illustration"
   or the user's language equivalent. Avoid fabricated numeric tick labels.
4. Use the actual slide size and theme. An optional layout is a light
   `F5F7FB` background, navy heading, white rounded central chart card, and
   two symmetric explanation cards below it. Use blue accents sparingly.
5. If useful, divide head and tail regions with a dashed line and subtle shading.
   Label each region directly. Make clear whether the boundary is illustrative
   or calculated from a documented criterion.
6. Keep titles, axis labels, legend, annotations, and card text readable.
   Aim for at least 14 pt body text. Shorten with approval or split dense content
   rather than shrinking labels.
7. Check labels, contrast, values, units, curve meaning, editability, and overlap.
   Ensure the chart does not imply unsupported precision, and report limitations.
